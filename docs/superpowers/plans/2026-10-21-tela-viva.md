# Tela Viva Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Tela Viva, a lightweight native Android TV app for discovering, configuring, and viewing up to four local IP cameras.

**Architecture:** Use one Android Activity with native Android Views, a local SQLite camera catalog, Android Keystore encryption for credentials, small platform-API ONVIF clients, and a Media3 RTSP playback coordinator. Keep network discovery, storage, playback, and TV navigation in separate packages; only camera streams that are visible stay active.

**Tech Stack:** Kotlin, Android Gradle Plugin 9.4.1 with Gradle 9.6/JDK 17, Android SDK 37 (min SDK 28, target SDK 37), Android Views, SQLiteOpenHelper, Android Keystore AES/GCM, and Media3 1.11.1. JUnit 4.13.2 and AndroidX Test 1.7.0/JUnit extension 1.3.0/Espresso 3.7.0 are test-only dependencies. Version choices were checked against the [Android build release references](https://developer.android.com/build/releases/about-agp), [Media3 RTSP documentation](https://developer.android.com/media/media3/exoplayer/rtsp), and [AndroidX Test releases](https://developer.android.com/jetpack/androidx/releases/test) on 2026-10-21.

**Spec:** `docs/superpowers/specs/2026-10-21-android-tv-camera-viewer-design.md`

## Global Constraints

- Minimum device: Fire TV Stick de 3ª geração, Fire OS baseado em Android 9 / API 28.
- Outros aparelhos Android TV ou TV Box com Android 9 ou superior.
- Local LAN only; no account, cloud, remote access, relay, telemetry, recording, or snapshot.
- Support ONVIF discovery and manual local IP/RTSP camera setup.
- Layouts: 1, 2, and 4 cameras; never keep more than four streams active.
- Live RTSP video: H.264; AAC or AC3 audio; audio is enabled only in fullscreen.
- In mosaics, prefer a lower-resolution substream; in fullscreen, use the main stream and release the other players.
- Persist camera names and addresses locally. Encrypt usernames and passwords with Android Keystore; never log credentials; deleting a camera deletes its saved credentials.
- All flows must work with the TV D-pad and show the current focus clearly.
- Validate on the Fire TV Stick target and a second real Android TV/TV Box; an emulator does not replace video and memory checks on hardware.
- `targetSdk 37` requires a runtime local-network permission on Android 17+. Request it only when the user starts discovery or connects to a camera; Android 9 devices do not show that permission prompt. [Android local-network permission](https://developer.android.com/privacy-and-security/local-network-permission)

## Review Focus

- Malformed, embedded-credential, or non-local RTSP addresses: reject before opening a socket; cover with `CameraAddressValidatorTest` and `LocalAddressPolicyTest` in Task 3.
- Empty, malformed, duplicated, or incomplete ONVIF discovery replies: show a useful empty/error state and retain manual setup; cover with `WsDiscoveryParserTest` and `OnvifProfileParserTest` in Task 3.
- Invalid credentials and cameras exposing H.265-only profiles: mark only that camera as incompatible/authentication-failed and allow retry; cover with `PlaybackFailureMapperTest` and ONVIF profile-selection tests in Tasks 3–4.
- Offline cameras and stream errors while other cameras are live: isolate the tile error and retain the other streams; cover with `PlaybackCoordinatorTest` in Task 4.
- Layout change, fullscreen return, app backgrounding, and D-pad traversal at four cameras: release hidden players, keep mosaic audio muted, restore the prior grid, and keep every action reachable; cover with `PlaybackCoordinatorTest` and `TvNavigationTest` in Tasks 4–5.

## Design Choices for Review

- **Native Views:** This plan uses platform Views to keep the runtime UI dependency set small and to use Android's built-in focus navigation. The tradeoff is that focus order and visual focus feedback must be tested explicitly. Android's current TV guidance recommends Compose for TV; it provides TV-specific components and simpler focus behavior, but adds UI toolkit dependencies. [Compose for TV guidance](https://developer.android.com/training/tv/playback/compose)
- **Android 17 local-network permission:** The app needs broad local-network access for direct RTSP and ONVIF multicast. With target SDK 37, discovery and playback require an explicit system permission on Android 17+. Explain this at the action that needs LAN access and handle denial without hiding manual setup.
- **Local-only endpoint rule:** Manual camera addresses and ONVIF-returned stream URLs must resolve to private or link-local addresses. Reject loopback, multicast, and public Internet destinations so a pasted remote RTSP URL cannot turn the app into a remote viewer.
- **ONVIF authentication:** Support the common WS-Security UsernameToken flow and HTTP Digest challenges. Keep credentials in memory only while a request is being formed, and do not log SOAP bodies, URLs containing credentials, or raw Media3 error text.

**Interfaces:**
- `LocalAddressPolicy.isAllowed(address: InetAddress): Boolean` allows RFC1918, IPv4 link-local, IPv6 ULA, and IPv6 link-local addresses; rejects loopback, multicast, and public addresses.
- `ValidatedCameraAddress(uriWithoutUserInfo: URI, resolvedAddress: InetAddress)` contains a credential-free URI and its checked local IP. `CameraAddressValidator.validate(uri: String): ValidatedCameraAddress` accepts credential-free RTSP URLs only when their resolved address passes `LocalAddressPolicy`.
- `LocalNetworkPermissionGate.ensureGranted(activity: Activity, action: LanAction, onResult: (Boolean) -> Unit)` immediately allows API <37 and requests `ACCESS_LOCAL_NETWORK` on API 37+ when discovery or connection is attempted; denial leaves setup usable and lets the user retry.
- `WsDiscoveryClient.discover(timeoutMs: Long): List<OnvifEndpoint>` sends a WS-Discovery Probe to multicast UDP port 3702, holds/releases the Wi-Fi multicast lock for the request only, deduplicates endpoints, and defaults to a 5000 ms timeout.

- `OnvifProfileSelector.select(profiles: List<OnvifProfile>): SelectedProfiles` returns the highest-resolution H.264 main token and lowest-resolution H.264 secondary token. Request their stream URIs afterward; `subRtspUri` is null if no second H.264 profile exists; H.265-only profiles return `UnsupportedCodec`.
- SOAP parsing uses the Android platform XML pull parser. Network calls use platform sockets and `HttpURLConnection`; do not add an ONVIF SDK.
